## Метрики Counter, Gauge, Histogram; pull-модель; labels; PromQL

### Часть 1. Counter, Gauge, Histogram

## 1.1. Counter - счётчик событий

**Counter** — монотонно растущее число: ошибки, запросы, заказы. Уменьшить нельзя. В экспозиции всегда появляется суффикс `_total`.

Правило: counter — это **счётчик событий**, а не «сколько сейчас чего-то».

| Метрика | Что считает |
|---|---|
| `http_requests_total` | Каждый HTTP-запрос (по method/path/status) |
| `orders_created_total` | Каждый созданный заказ — бизнес-метрика |
| `payment_failures_total` | Каждая неудача оплаты — вход в алерт |
| `cas_update_conflicts_total` | Конфликты CAS-переходов статусов |

## 1.2. Gauge — текущее значение

**Gauge** — значение, которое может расти и падать: «сколько сейчас». Не считается, не суммируется — снимается мгновенный снимок.

| Метрика | Что показывает |
|---|---|
| `pool_connections_in_use` | Занятые соединения пула БД (max_size=10). После рефакторинга дня 12 она должна «дышать»: подскок на миллисекунды INSERT'а, а не залипание на 10 всю «поездку» |
| `rabbitmq_queue_depth` | Глубина `order_queue` (через exporter) — заготовка алерта «консьюмер умер» |
| `process_resident_memory_bytes` | Память процесса (default-метрика клиента) |
| `in_flight_orders` | Заказы в промежуточных статусах — цена изоляции саги, видимая метрикой |

## Histogram — распределение значений

Histogram — распределение значений по заранее известным корзинам, каждое наблюдение (например, время ответа) инкрементирует все корзины, чья граница ≥ значения. 

**Внутри обычно хранят**
1. Сумму всех значений (_sum)
2. Общее количество наблюдений (_count)
3. Счетчик по бакетам (_bucket={le="..."}) - сколько значений попало в каждую корзину.

**Пример**
- Бакеты: 0.1с, 0.5с, 1с, 5с

100 запросов уложились за 0.1 le= "0.1" = 100 запросов
еще 50 запросов уложились за 0.5 le= "0.5" = 150 запросов
еще 10 запросов уложились за 1 le= "1" = 160 запросов
еще 5 запросов уложились за 5 le= "5" = 165 запросов

- Из этого потом можно считать квантили, например p95=1с, означанет что 95 % запросов оказалось быстрее 1с.

# Часть 2. Почему pull: Prometheus сам забирает метрики

Prometheus - это инструмент мониторинга и оповещения, который делает три вещи:
1. Собирает метрики
2. Хранит метрики
3. Позволяет запрашивать метрики

**Как он это делает и зачем**
- Prometheus по расписанию делает HTTP GET на `/metrics` каждого зарегистрированного сервиса и забирает оттуда текущие значения метрик.

1. Обнаружение проблемы = отсутствие ответа
2. **Отказозащищённость направления.** При инциденте падает приложение — мониторинг продолжает опрашивать остальных. Push наоборот: система мониторинга — точка сбоя для всех, и в момент аварии очередь push'ей забита.

##  Scrape interval

`scrape_interval` — период опроса  обычно ставят 15–30 сек.

- Применяется для алертов, опрос идет каждые 15 секунд и если в течение минуты все запросы привысили граничное значения, то приходит алерт.

**Пример**

- Если p99 времени ответа больше 2с и так держится на протяжении минуты то тогда алерт

Label — пара `key="value"`, добавляющая измерение к метрике и описывают её контекст.

# PromQL: rate, increase, histogram_quantile


## rate()

- Показывает, как быстро растет Counter за последнюю секунду

```
rate(http_requests_total[5m])
```

- Считает количество запросов в течение 5 минут и потом находит количество запросов в секунду.

**Например**

- 3000 запросов за 5 минут, 3000/300 = 10 запросов в одну секунду.

**Когда используем**

1. Для мониторинга нагрузки (RPC)
2. Для алертов, если скорость ошибок привышает Х, то приходит уведомление.

## increase()

- Показывает, на сколько увеличился Counter за указанный период

```
increase(orders_created_total[1h])
```
- Считает сколько было запросов за один час

**Когда используем**

1. Для подсчета заказов за день, неделю, месяц либо год.
2. Для алертов если было сделано больше 1000 ошибок то уведомление приходит

## histogram_quantile()

- Берет данные Histogram и вычисляет перцентиль

```
histogram_quantile(0.95,
  sum by (le) (rate(http_request_duration_seconds_bucket[5m]))
)
```

- Посмотри на распределение времени ответа за последние 5 минут и найди значение, быстрее которого выполняются 95% запросов.
