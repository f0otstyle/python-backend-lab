# SPEC: exp5 — отказоустойчивый клиент и нестабильный стенд

## Цель

Эксперимент над отказоустойчивостью: стенд имитирует нестабильный сервис
(первые N запросов — 503), клиент добивается успеха через повторные попытки
с экспоненциальным backoff + jitter и предохранитель CircuitBreaker.
Папка `loop-lab/exp5/`, стиль и соглашения — как в соседних exp (AGENTS.md).

## Шаги

1. **Стенд `server.py`**: FastAPI, `/flaky` отвечает 503 на первые `FAILS_N = 3`
   запросов, затем 200 (счётчик в памяти стенда); `/health` → `{"status": "ok"}`
   как в exp1/exp2; русский докстринг, запуск `uvicorn server:app --port 8000`.
2. **Клиент `client.py`** (async, aiohttp, константы вверху, `LAB_URL`):
   - `fetch_with_retry()` — до `MAX_RETRIES = 5` попыток, задержка
     `BACKOFF_BASE = 0.2 c * 2**attempt` + full jitter; транспорт инъецируется
     аргументом (любой объект с async-методом, возвращающим ответ со `.status`).
   - класс `CircuitBreaker(k=3, timeout=2.0)`: `closed` → `open` после K подряд
     неудач → `half-open` через таймаут → `closed` после первого успеха;
     отказ в `half-open` возвращает в `open`; часы инъецируются для тестов.
   - счётчики попыток/успехов/отказов, печать `Итог: N/M` в конце.
3. **Тесты `test_client.py`, `test_server.py`** (pytest, без реального HTTP):
   - клиент — фейковый транспорт (мок с очередью ответов), проверяются:
     retries/backoff (последовательность задержек, jitter через seed/инъекцию),
     переходы CircuitBreaker closed→open→half-open→closed и обратно в open.
   - стенд — fastapi TestClient: `/flaky` 503×N затем 200, `/health`.
4. **TDD**: субагенты в изолированных worktrees, red → green.
5. **Сборка**: файлы из worktrees переносятся в `loop-lab/exp5/` основной
   папки (без коммитов — по решению пользователя), финальный прогон
   `pytest` и `py_compile`.

## Критерии готовности (DoD)

- [ ] `python -m py_compile server.py client.py` — чисто.
- [ ] `pytest` в exp5 зелёный; сначала был red (тесты до реализации).
- [ ] TestClient: `/flaky` — 503 ровно N раз, затем 200; `/health` → `{"status": "ok"}`.
- [ ] Фейковый транспорт: 2 отказа → 200 → `fetch_with_retry` возвращает успех
      после 3-й попытки; 5+ отказов подряд → исчерпание попыток, отказ.
- [ ] CircuitBreaker: 3 подряд неудачи → `open`; запрос в `open` отклоняется
      без вызова транспорта; после таймаута → `half-open`; успех → `closed`,
      отказ → снова `open`.
- [ ] Демо-сценарий клиента печатает `Итог: N/M` (живой запуск стенд+клиент —
      ручная проверка пользователя, сервер без его просьбы не стартуем).

## Границы

- Только существующие зависимости лабы: fastapi, aiohttp, pytest (requirements.txt).
- Не трогаем соседние `exp<N>/`, корень лабы, AGENTS.md; git-коммиты запрещены.
- Стиль exp-файлов: русский докстринг/логи, константы вверху, `LAB_URL`.
- Никакого реального HTTP в тестах: TestClient и мок-транспорт, сокетов нет.
- Retry применяется только к 5xx (503); 4xx не ретраится — сразу отказ.
- Без деплоя, Docker, мониторинга — учебный самодостаточный эксперимент.
