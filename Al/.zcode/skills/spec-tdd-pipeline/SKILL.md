# Пайплайн разработки: Spec -> TDD -> Worktree

Выполняй шаги строго по порядку. Не пропускай и не меняй местами.

## Шаг 1: Опрос и Спецификация (SPEC.md)
1. **Опрос**: Задай пользователю уточняющие вопросы по задаче. Выясни граничные случаи, ожидаемое поведение и критерии готовности. Не начинай писать код, пока не получишь ответы.
2. **Создание SPEC.md**: На основе ответов создай в корне проекта файл `SPEC.md`. В нем обязательно должны быть разделы:
   - **Цель**: Что делаем и зачем.
   - **Шаги**: Высокоуровневый план реализации.
   - **Критерии готовности (DoD)**: Что должно работать, чтобы задача считалась выполненной.
   - **Границы**: Что мы точно НЕ трогаем в этом коде (чтобы агент не лез в другие модули).
3. Запроси у пользователя подтверждение `SPEC.md` перед продолжением.

## Шаг 2: Планирование и Изоляция (Git Worktree)
1. Проанализируй `SPEC.md` и разбей задачу на **независимые** подзадачи (например: UI-компонент, API-эндпоинт, Тесты).
2. Для каждой подзадачи создай изолированное рабочее окружение через терминал:
   `git worktree add ../<имя_подзадачи> -b feature/<имя_подзадачи>`
3. Создай файл `TASKS.md` в корне основной ветки, где перечисли созданные папки (worktree) и назначь каждой задаче своего субагента.

## Шаг 3: Параллельный TDD (Субагенты)
Для КАЖДОЙ подзадачи из `TASKS.md` запусти изолированного субагента (например, `general-purpose`). В инструкции субагенту укажи:

- **Рабочая директория**: `../<имя_подзадачи>` (работай только там).
- **Контекст**: Прочитай `SPEC.md` из этой директории. Твоя задача: <описание подзадачи>.
- **Методология (TDD)**:
  1. **RED**: Напиши падающие тесты для своей подзадачи. Запусти их (`npm test` или аналог). Убедись, что они красные.
  2. **GREEN**: Напиши минимальный код, чтобы тесты стали зелеными. Не меняй тесты.
  3. **Цикл**: Если тесты упали, исправляй код, пока все не станет зеленым.
- **Запрет**: Не выходи за рамки своей рабочей директории и не трогай файлы других субагентов.

## Шаг 4: Сборка и Ревью (Merge)
1. Дождись, пока все субагенты отчитаются об успешном прохождении тестов (зеленый статус).
2. Переключись на основную ветку (`git checkout main`), иначе слияние уйдёт не в неё.
3. Для каждой успешной ветки запусти команду слияния:
   `git merge feature/<имя_подзадачи>`
4. Если возникли конфликты — разреши их (можно поручить субагенту или сделать вручную).
5. После слияния всех веток запусти полный набор тестов в основной ветке (`npm test` или аналог для проекта), чтобы убедиться, что интеграция не сломала проект.
6. Выведи пользователю итоговый отчет: какие файлы изменены, какие тесты добавлены, и предложи ручную проверку.
